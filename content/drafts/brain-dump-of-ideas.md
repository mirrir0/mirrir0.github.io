I'm going to just dump a bunch of the ideas that I have for company work into one document. 

The first thing that I can think of is that I want to be building anomalous as a kind of hyper-specific democratization system. I want it to be a platform where I am building as much flexibility for end users as possible, primarily because I do not think that we can really decide winners and losers in the agent economy right now. 

Because of this, I think that there is a specific requirement for how I am going to be dealing with agent marketing as well as agent tooling. The main thing that I can think about when it comes to anomalous is that I want to be able to regularly, continually push the improvement of internal agent systems without putting us into an inflexible, difficult-to-access, and difficult-to-move-out-of position. 

Because of this, I think that there is a way for me to be handling each category of the product build system. 

This is the reason that we have waddling. Modeling is supposed to be a data backbone for a bunch of other workflows and use cases and supposed to be as flexible as possible. Of course, I need to actually present the value adds for it, but one of the main things with that is that I do not want to really be thinking about fighting at the agent layer as much as I want to be fighting at the incremental gain calculation layer. 

The idea here is that we want to be able to build effectively super memory, but going beyond how super memory itself handles what it does, because super memory is about having agents be able to remember things. I want Anomalous to be able to remember how people do things together in general. 

One of the things with Anomalous is being able to build an MCP app platform and protocol layer that allows us to very directly and very effectively leverage Duck DB and things like it to be able to create multiplayer multi-agent apps using layers and layers of agents operating inside of quack-based Duck DB clusters. 

For me, the issue with Anomalous is that Anomalous is supposed to be something like an operating system or a pivot system where you can connect your agents to that, and then you can use it to flexibly work with and work through exactly what it is that you are doing. 

What I realized in building that is that if I can't build flexible data systems that are able to adapt to each other, I can't actually build the necessary operating system for the context of those agents.
