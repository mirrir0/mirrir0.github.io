I think that we need to build tools that facilitate us understanding, enabling, and extending our understanding of processes. That means that we also need to be able to have user tools that don't simply allow us foot-guns. They also have to allow us to be able to clearly and specifically address what our desiderata actually are.\
\
Without being able to fundamentally feel in tune with the tooling that we use, we end up needing to create hacks, inadequate implementations, and/or illusions of competence. If we want to be building GOOD things, none of the above are really acceptable. \
\
If this is the case, then we need tools that allow us to be working from the back to the front of the process of building software. We need to create more than just notebooks. We need tooling that can allow us to scale from purely AI generated code to code that we are actually accountable to and through that something that is understood and extensible.

This means building accountable, modifiable, and plastic tooling that molds to the discoveries of the user to the tasks at hand. 

this means that we need to be able to create environments that allow users to do whatever the fuck they want, and to be able to help them along the way.
